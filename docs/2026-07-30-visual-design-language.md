# 前端视觉设计语言与落地方案

日期：2026-07-30

范围：`client/` 全部界面 —— design token、组件外观、布局结构
目标：把当前散落在各组件里的 60+ 个自定义视觉数值，收敛成一套可以推导、可以校验的设计语言。

配套的可交互样张（色板、高度阶梯、材质、圆角嵌套、字阶、状态全部真渲染，可切主题对比）：
<https://claude.ai/code/artifact/918f8c3e-ffea-4453-a410-0fb053227e56>

## 1. 结论

问题不是「不够好看」，是**没有系统**。当前每个组件自己发明阴影、自己发明透明度、自己发明圆角，
所以界面缺的不是装饰，而是光学一致性。

方案的核心不是换一套更贵的颜色，而是**把发明数值的权利收回到 token 层**：
组件只被允许引用等级（`--e2`、`--label-2`、`--fill-1`），不允许写数字。

- 应新增：中性阶梯、四级高度阶梯、材质定义、圆角阶梯、全局状态定义（纯新增，不动组件）。
- 应替换：10 个文件里 60+ 处硬编码 `white/N`、`slate-N`；12 种阴影收敛成 4 级。
- 应删除：助手消息气泡外壳；不透明面板上的 `backdrop-blur`；侧边栏的浮空圆角卡外观。
- 应保留：语义标记（thesis/risk/metric/level/catalyst/unverified/cite）的配色契约、图表的全部视觉 ——
  那套已经是对的，只需要把 amber/sky/emerald/rose 接到语义 token 上。
- **不做**：不引入自定义字体（理由见 §11）。

## 2. 现状审计

对 `client/src` 的实际统计（非估计）：

| 症状 | 计数 | 后果 |
| --- | --- | --- |
| 任意值阴影 `shadow-[…]` | 6 种 | 再加 6 档命名阴影（`shadow-sm/md/lg/xl/2xl/inner`），全 app 共 **12 个互不相关的「高度」**。没有光源一致性，每块面板都像单独贴上去的。 |
| 硬编码 `white/N`、`black/N` | 60+ 处 | 其中 `border-white/10` 出现 18 次 —— 它在浅色模式下**完全不可见**。这不是风格问题，是 bug。 |
| 硬编码 `slate-N`、`gray-N` | 60+ 处 | 绕过了 `--background` / `--foreground` token，主题切换时这些值不跟随。 |
| 圆角种类 | 10 种 | 嵌套时内外圆角随机，视觉上会看到「壳没有包住内容」。 |
| 模糊档位 | 5 档 | 用在了不透明面板上 —— 那里没有背景可透，纯粹是合成层开销。 |

复现命令：

```
cd client/src
grep -rhoE 'shadow-\[[^]]*\]' . | sort | uniq -c | sort -rn
grep -rhoE '(bg|border|text|ring)-(white|black)/[0-9]+' . | sort | uniq -c | sort -rn
grep -rhoE 'rounded-(none|sm|md|lg|xl|2xl|3xl|full|\[[^]]*\])' . | sort | uniq -c | sort -rn
```

## 3. 第一性原理

六条。每一条都能直接推出一条工程规则；推不出规则的不写进来。

### 3.1 只有一个光源，所有元素都服从它

光从上方来。因此阴影永远向下偏移、永远不对称；抬起的表面顶边有一道更亮的**轮廓光**
（`inset 0 1px 0`），底边更暗。

当前代码里没有任何轮廓光 —— 这是面板「贴上去」而不是「浮起来」的直接原因。

### 3.2 阴影是两层的：接触 + 环境

真实物体有一道紧贴边缘的**接触阴影**（1–2px，透明度较高，把物体钉在页面上），
和一大片**环境阴影**（大模糊半径，透明度极低）。单层阴影一定显廉价。

这是投入产出比最高的一条。

### 3.3 分隔靠光，不靠线

半透明表面上的「边框」其实是**边缘光**：顶部比表面亮、底部比表面暗。
纯色表面上的分隔线只用 8–12% 透明度 —— 当前代码里大量 20%+ 的线，读起来像草稿网格。

### 3.4 半透明必须提饱和度

`backdrop-filter: blur()` 单独用会把背后的颜色洗成灰，材质就死了。
真实的做法是 `blur(30px) saturate(180%)`。**这一条是仿品和真品差距最大的地方。**

而且模糊只用在「下面确实有内容继续延伸」的图层上；不透明面板上用模糊纯属浪费。

### 3.5 圆角随尺寸缩放，且必须嵌套

内圆角 = 外圆角 − 内边距。两个同心同半径的圆角一定看起来不对。
大面板用大圆角、小控件用小圆角，不是全局一个值。

### 3.6 chrome 是无彩色的，颜色只在有含义时出现

界面骨架全灰。颜色只留给两件事：**强调色**（可交互 / 已选中）和**语义色**（涨 / 跌 / 风险）。

这一条语义标记已经做对了，chrome 还没跟上。

## 4. 中性色与语义色

全部带 220° 冷偏，沿用现有的 `--background: 220 15% 97%`。纯中性灰读起来像没考虑过。

前景色只有四档、填充只有三档 —— 任何组件必须从里面挑一档，不许自己调透明度。

```css
:root {
  /* 表面 */
  --canvas:  #EFF1F5;   /* 最底层画布 */
  --surface: #F7F8FA;   /* 面板 / 侧栏 */
  --raised:  #FFFFFF;   /* 卡片 / 浮层 */

  /* 前景四档 */
  --label-1: rgba(11,14,20,.92);  /* 正文 */
  --label-2: rgba(11,14,20,.60);  /* 次要 */
  --label-3: rgba(11,14,20,.38);  /* 辅助、标签 */
  --label-4: rgba(11,14,20,.22);  /* 禁用、滚动条 */

  /* 填充三档 —— 交互状态唯一允许的手段 */
  --fill-1: rgba(11,14,20,.05);
  --fill-2: rgba(11,14,20,.08);
  --fill-3: rgba(11,14,20,.12);

  /* 分隔 */
  --sep:        rgba(11,14,20,.10);
  --sep-strong: rgba(11,14,20,.18);
  --rim:        rgba(255,255,255,.85);   /* 轮廓光 */

  /* 强调 —— 全 app 唯一 */
  --brand:     #0A6CD8;
  --brand-sub: rgba(10,108,216,.10);

  /* 语义 —— 只用于数据，不用于 chrome */
  --up:   #0B7A4B;
  --down: #C22B4A;
  --hold: #A8720C;
}

.dark {
  --canvas:  #070A11;
  --surface: #0D111A;
  --raised:  #151A25;

  --label-1: rgba(251,252,253,.94);
  --label-2: rgba(251,252,253,.58);
  --label-3: rgba(251,252,253,.36);
  --label-4: rgba(251,252,253,.20);

  --fill-1: rgba(255,255,255,.05);
  --fill-2: rgba(255,255,255,.09);
  --fill-3: rgba(255,255,255,.14);

  --sep:        rgba(255,255,255,.10);
  --sep-strong: rgba(255,255,255,.18);
  --rim:        rgba(255,255,255,.07);   /* 深色下轮廓光是白的、很淡 */

  --brand:     #4C9DFF;
  --brand-sub: rgba(76,157,255,.14);

  --up:   #3ECF8E;
  --down: #FF6B85;
  --hold: #E5A93C;
}
```

**语义色在深色模式下必须重新取值，不能只调亮度**：深底上的绿要往青偏、红要往粉偏，
否则在 `#070A11` 这种深蓝底上会发脏。上面已经是两套独立取值。

## 5. 高度：四级阶梯

每一级是一个固定三元组：**背景 + 边框 + 阴影**。组件只能选级别，不能自己写 `shadow-[…]`。

```css
:root {
  --e1: 0 .5px 1px rgba(11,14,20,.05), 0 1px 3px -1px rgba(11,14,20,.07);
  --e2: 0 1px 2px rgba(11,14,20,.06), 0 8px 24px -8px rgba(11,14,20,.16);
  --e3: 0 2px 4px rgba(11,14,20,.06), 0 28px 64px -16px rgba(11,14,20,.26);
}
.dark {
  --e1: 0 .5px 1px rgba(0,0,0,.40), 0 1px 3px -1px rgba(0,0,0,.50);
  --e2: 0 1px 2px rgba(0,0,0,.50), 0 8px 24px -8px rgba(0,0,0,.70);
  --e3: 0 2px 4px rgba(0,0,0,.50), 0 28px 64px -16px rgba(0,0,0,.85);
}

/* 每一级都要带轮廓光 */
box-shadow: var(--e2), inset 0 1px 0 var(--rim);
```

| 级别 | 阴影 | 用在哪里 |
| --- | --- | --- |
| **E0 齐平** | 无，只有 `--sep` 分隔线 | 图表面板、消息列表、表格、侧栏列表项。**绝大多数东西属于这一级。** |
| **E1 抬起** | `--e1` + 轮廓光 | 来源卡片、指标卡 |
| **E2 浮空** | `--e2` + 轮廓光 | 引用悬浮卡、下拉菜单、输入区 |
| **E3 模态** | `--e3` + 轮廓光 | 对话框、审批弹窗。全 app 同时最多存在一个。 |

## 6. 材质

只有三处满足「下面真的有内容继续延伸」这个条件：

1. **侧边栏** —— 盖在画布上
2. **输入区** —— 盖在消息流上
3. **图表面板表头** —— 内容从下方滚过

其余全部改成不透明。

```css
:root {
  --material:    saturate(180%) blur(30px);   /* 饱和度是关键，不是模糊 */
  --material-bg: rgba(255,255,255,.72);
}
.dark { --material-bg: rgba(13,17,26,.72); }

.material {
  background: var(--material-bg);
  backdrop-filter: var(--material);
  border-bottom: 1px solid var(--sep);   /* 材质边缘必须有一道线收口 */
}
```

## 7. 圆角

随尺寸缩放，不是全局一个值：

| token | 值 | 用途 |
| --- | --- | --- |
| `--r-xs` | 5px | 徽章、引用角标 |
| `--r-sm` | 7px | 按钮、chip |
| `--r-md` | 9px | 输入框、列表项 |
| `--r-lg` | 12px | 卡片 |
| `--r-xl` | 16px | 面板 |
| `--r-2xl` | 20px | 模态 |

**嵌套公式：内 = 外 − 内边距。** 外壳 16px、内边距 8px，则内层必须是 8px。

当前 `--radius: 0.625rem` 已在上一轮从 1rem 收紧，这一步是把单值换成阶梯。

## 8. 文字

不引入新字体（理由见 §11）。质感来自**字距曲线**和**字重节制**：
字号越大字距越负，小型大写放开；全 app 只用 400 / 600 / 700 三档字重。

| 角色 | 字号 | 字重 | 字距 | 行高 |
| --- | --- | --- | --- | --- |
| 回答标题 | 32 | 700 | −0.022em | 1.1 |
| 章节 H2 | 22 | 650 | −0.016em | 1.25 |
| 小节 H3 | 17 | 650 | −0.008em | 1.35 |
| 正文 | 15 | 400 | 0 | 1.65 |
| 次要 / 表格 | 13 | 400 | 0 | 1.5 |
| 章节标签（`.fin-label`） | 11 | 650 | +0.14em UC | 1 |
| 数字（`.fin-figure`） | 13 | 400 | mono, tnum + zero | — |

`.fin-figure` 和 `.fin-label` 已存在，保留不动。

## 9. 状态：定义一次，全局复用

当前每个组件自己发明 hover 效果。改成：所有可交互元素**只加一层填充**，
选中态才动颜色，焦点环全局统一。

| 状态 | 表现 |
| --- | --- |
| 静止 | 透明 |
| 悬停 | `--fill-1` |
| 按下 | `--fill-2` |
| 选中 | `--brand-sub` 填充 + 2px `--brand` 边条 |
| 键盘焦点 | `outline: 2px solid var(--brand); outline-offset: 2px` |
| 禁用 | `--label-4`，无填充 |

| --- | --- | --- | --- |

## 11. 动效

浮层从触发它的位置生长出来（`transform-origin` 对准触发点），不是淡入。
时长 160–280ms，曲线 `cubic-bezier(.2,.7,.3,1)`。

列表项、消息、图表**不做入场动画** —— 流式输出本身已经是运动了，再加会晕。
全部包在 `prefers-reduced-motion` 里。

## 12. 一条反建议：不要引入自定义字体

这个产品是中英混排。任何拉丁显示字体在中文段落里都会退化成系统字体，
结果是同一句话里两种字型 —— 比统一用系统字体难看得多。

苹果的「高级」从来不来自字体本身（系统字体就是它的字体），
而来自 §3 那六条对光、材质、层级的一致性。

## 13. 落地步骤

每一步可单独提交、单独回退。1–2 步做完就能看出大部分差别。

| # | 步骤 | 内容 | 风险 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 铺 token 层 | 往 `index.css` 加中性阶梯、高度阶梯、材质、圆角、状态，并在 `tailwind.config.ts` 里暴露成 `bg-surface` / `text-label-2` / `shadow-e2-rim` / `rounded-lg` 这类工具类。纯新增，不动任何组件。 | 零 | ✅ 2026-07-30 |
| 2 | 清硬编码颜色 | 10 个文件里的 `white/N`、`slate-N` 全换 token。顺带修掉浅色模式下不可见的 18 处 `border-white/10`。 | 低，逐文件截图对比 | ✅ |
| 3 | 阴影收敛 | 12 种阴影 → 4 级，全部加轮廓光。**视觉变化最明显的一步。** | 中，两套主题都要过 | ✅ |
| 4 | 删助手气泡 | 改 `chat.tsx` 消息渲染结构。唯一动布局的一步。 | 高，影响所有历史消息渲染 | ✅ |
| 5 | 字距 + 材质收口 | 字阶接上负字距，模糊从不该用的地方撤掉。 | 低 | ✅ |

### 落地时发现的两处偏差

- **`--accent` 撞名。** shadcn 已经用 `--accent` 存了一个 HSL 三元组（`bg-accent` 的悬停态靠它）。
  设计语言里的强调色改名 **`--brand`**，并存成 RGB 三元组 `--brand-rgb`，
  这样 Tailwind 的 `/N` 透明度修饰（`border-brand/50`）才有效。`--up` / `--down` / `--hold` 同理。
- **引用的 sky 合并进 `brand`。** §3.6 只允许一个强调色，而「引用 = 别人的原话」正是可交互外链的角色，
  两者本来就该是同一个颜色。原来的 sky-500/600/700 全部收敛。

## 14. 验收标准

- `grep -rhoE 'shadow-\[[^]]*\]' client/src` 只应剩 token 定义本身
- `grep -rhoE '(bg|border|text|ring)-(white|black)/[0-9]+' client/src` 应为空
- 浅色 / 深色两套主题下，每个组件的分隔线都可见且强度一致
- 每个浮层的圆角与其内容的圆角满足 `内 = 外 − padding`
- 控制台无警告，`npm test` 与两个 tsc project 全绿
