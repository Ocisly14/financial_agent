## 1. 目标与非目标

### 目标
1. 对任意 `StrategyDSL` 跑历史 **P&L 回测**,复用 A 的 `StrategyEngine.evaluate`(单一代码源:回测 ≡ 实盘)。
2. 提供 `HistoricalSignalContext`——SignalContext 的历史实现,把价格/TA/链上/情绪按同一时间轴对齐。
3. 自建**历史数据缓存/快照**,让回测回溯更深、更快更稳。
4. 成交模拟含**手续费 + 滑点**,产出**标准指标 + buy-and-hold 基准对照**。
5. 新增 `cex_backtest_strategy` 工具,agent 可在部署前先回测 draft。
6. 提供**参数扫描接口**,供 C 的优化内环调用。

### 非目标
- 生成→回测→优化内环、LLM 结构性修改 → **子系统 C**。
- 组合级/多标的回测 → 远期。
- A 已定的信号分类法与 engine → 不在此重复。

## 2. 组件边界与数据流

```
       ┌─────────────────────────────────────────────┐
       │            历史数据缓存 (新)                  │
       │  采集器 → 本地快照存储(价格/链上/情绪)      │
       └─────────────────────────────────────────────┘
                         │ 读
                         ▼
       ┌─────────────────────────────────────────────┐
       │        HistoricalSignalContext               │  ← 实现 A 的 SignalContext 接口
       │  (按时间轴对齐 + 缺数据标"不可用")           │
       └─────────────────────────────────────────────┘
                         │ valueOf(signalId, t)
                         ▼
       ┌─────────────────────────────────────────────┐
       │   Backtest Runner (移植 staging runner.ts)   │
       │  逐时间步:StrategyEngine.evaluate →          │
       │  OrderIntent → 成交模拟(费+滑点)→ 记账      │
       └─────────────────────────────────────────────┘
                         │
                         ▼
       ┌─────────────────────────────────────────────┐
       │           BacktestReport                     │
       │  指标 + buy-and-hold 基准 + 不可回测信号标注  │
       └─────────────────────────────────────────────┘
```

四个组件,各自单一职责:

- **历史数据缓存**:后台**同时采集价格 + 链上 + 情绪**三类并落本地快照,各源能拉多深拉多深;对外只提供"某源在 [t0,t1] 的序列"。回溯深度由各源上限决定。
- **HistoricalSignalContext**:实现 A 的 `SignalContext`;负责§4 的对齐语义与"不可用"判定。与 `LiveSignalContext` 行为对齐 → 回测=实盘。
- **Backtest Runner**:纯计算循环,驱动 `StrategyEngine.evaluate`;成交经费/滑点模型 + 复用 riskEngine。移植 staging `backtest/runner.ts`+`indicators.ts`。
- **BacktestReport**:见 §3。

## 3. 报告口径(BacktestReport)

- **标准指标**:总收益、Sharpe、最大回撤、胜率、交易数、平均持仓时长、敞口。
- **基准对照**:同区间 **buy-and-hold** 收益,给出**超额收益**(策略 − 持有)。这是 C 优化内环目标函数的首选。
- **资金曲线(equity curve)**:本轮产出,供人/前端看回撤形状,也供 C 参考。
- **不可回测信号**:`unbacktestable_signals[]` —— 策略用到但历史缺数据的信号,明确标注(顶层"降级回测 + 明确标注")。
- **逐笔成交明细**:**后置**(不在本轮),需要时再补。

---

## 4. 时间轴对齐(最难的缝)

- **信息保真契约(硬约束,继承顶层 §7)**:`valueOf(id, t)` 只能返回「在 t 时点真实可得」的值,绝不返回未来值——历史以「当时观察到什么」为准构建,而非事后回填终值。链上/情绪高危(发布滞后 + 事后修正),否则前视偏差会让 optimizer 朝作弊通道优化。具体实现手段(前向记录 / lag 字段 / 版本化快照)在本子系统 plan 阶段定,概念层只钉住"绝不使用未来值"。
- 各源频率不同(K 线分钟级、链上小时级、情绪日级)。`HistoricalSignalContext` 定义每源的**取值语义**(前向填充 vs 拒绝)与**可用窗口**。
- 某信号在某 t 无数据 → `valueOf` 返回"不可用";StrategyEngine 按 A 的契约(不可用比较为 false)处理。
- 实盘 `LiveSignalContext` 用相同"缺数据=不可用"语义 → 回测与实盘一致。

---

## 5. 成交真实度

- **手续费**:maker/taker 分档,口径与 paper venue 对齐。
- **滑点**:固定 bps 起步,预留基于波动/深度的模型位。
- 回测成交同样过 **riskEngine**(与实盘一致的风控)。
- ⑤ 评测:同输入(含费/滑点参数)回测两次,指标逐位一致。

---

## 6. 参数扫描接口(供 C)

- 提供"固定策略结构、遍历指定参数网格 → 批量回测 → 返回各组指标"的接口。
- B 只负责**执行扫描并返回结果**;"选哪个、要不要继续、LLM 怎么改结构"是 C 的编排职责。

---

## 7. 已敲定的概念决策

1. **报告粒度**:汇总指标 + buy-and-hold 基准 + **资金曲线**;逐笔成交明细后置。
2. **采集范围**:价格 + 链上 + 情绪**三类一起采**,各源能拉多深拉多深。
3. **区间与步长**:步长 = **策略用到的最细信号频率**(含分钟级信号就 1m,纯日级就日线);默认区间给合理值(如近 90 天)且可覆盖。与实盘评估频率对齐、计算量自适应。

---

## 8. 交付边界(B 完成即)

给定一份 strategyDSL + 区间 → 得到含标准指标与 buy-and-hold 基准的 BacktestReport;缺数据信号被标注;agent 可经 `cex_backtest_strategy` 在部署前回测;参数扫描接口就绪供 C 调用。**优化内环仍不存在(C)。**
