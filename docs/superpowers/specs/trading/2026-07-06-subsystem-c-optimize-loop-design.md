## 1. 目标与非目标

### 目标
1. 实现部署前的 **生成→回测→优化** 迭代内环(QuantAgent writer/judge 形态)。
2. 双驱动优化:**参数扫描**(调 B 的扫描接口,确定性)+ **LLM 结构性修改**(读 BacktestReport 换信号/加止损/改逻辑)。
3. **防过拟合(walk-forward 滚动验证)**:多 fold 样本外 + robust-max 调参 + embargo + 按试验次数打折;跨 fold 汇总达标才入选。
4. **冻结部署 + 衰减/失效**:部署冻结对象(零自动参数变动),度量衰减、并以回测分布推出的失效线做 kill-switch(硬触发只停手)。
5. **后台任务 + 进度上报**执行,不阻塞对话。
6. 候选部署受 mode 约束:**paper/shadow 自动、live 必审批**(保留顶层安全不变量)。
7. **绩效记忆(填充顶层长期记忆)**:L1 per-strategy 绩效日志 + **L2 跨策略教训记忆**(一等组件)+ **实盘 vs 回测 divergence** 校准。这些均为顶层"trade subagent 长期记忆"的**策略绩效内容**(另一类内容"用户偏好"在顶层定义);短期/长期两层记忆架构见顶层 §6。

### 非目标
- A 的信号/engine、B 的回测/数据缓存 → 不在此重复。
- 组合级优化、跨策略进化 → 远期。
- **L3 市场状态/regime 记忆**(长期市况画像、跨市场偏好)→ 远期,本轮只做 L1/L2。
- 改模型权重 → 明确不做(仅语言反馈 + 记忆)。

## 2. 内环编排(Optimizer)

两层结构(勿混):**参数扫描 = 结构*内*的数值优化;LLM 结构编辑 = 结构*间*的语义搜索**。任何结构在比较前都先被扫参到"它自己的最优参",否则拿调好参的和没调参的比不公平。

```
初始 StrategyDSL(agent 生成)+ 优化预算(目标/封顶轮数)
        │
        ▼
 ┌──► 每轮(外层:LLM 结构搜索):
 │      1. 对当前结构,跑 §4 的 walk-forward + 粗到细扫参(内层)
 │           → 得到该结构"最优参下"的【标量分】+【诊断摘要】
 │      2. LLM 读【诊断摘要】(按 regime 拆分的弱点归因)→ 产出结构改动版 vN+1
 │      3. 给 vN+1 同样跑 walk-forward → 标量分
 │      4. keep-best:标量分更高则替换当前最优
 │           记 {版本, 参数, 每fold, per-regime, 分} → 优化轨迹 + L1
 │      │
 │      ▼
 │   停止判定:目标达成 或 连续 K 轮无提升 或 封顶轮数 或 算力预算耗尽
 └──────┘  否则继续
        │
        ▼
 冠军结构 → 用【最近窗口调一次参】得到上线参数(见 §4 冻结部署)
        → 部署(paper/shadow 自动;live 发 approval)
```

- **Optimizer** 是唯一编排者:内层扫参交给 B(§4 walk-forward 的编排在 C,B 只提供"单区间回测"与"参数网格扫描"两个原子能力),外层 LLM 改结构在 C。
- 一份 walk-forward 报告**劈成两半用**:①**标量分**(§4 的 median−λ·dispersion+灾难门)供 keep-best 冷比较;②**诊断摘要**(跨 fold 分布、按 regime 拆分、弱点归因)供 LLM 改结构。**结构编辑质量完全取决于报告被蒸馏成多可执行的诊断**——给 LLM"你在震荡市亏钱"它能加过滤器,给它一个裸 Sharpe 它只会瞎改。

## 3. 目标函数

- **默认**:风险调整后的**超额收益**——以对 buy-and-hold 的超额为主,对回撤/波动惩罚(如 Sharpe 或 超额/最大回撤)。
- **用户偏好可覆盖**:创建时可指定偏好(更激进=偏超额、更稳=偏低回撤),Optimizer 据此调目标函数权重。
- 择优与停机判定**一律以样本外指标为准**(具体为 §4 的跨 fold 汇总分),避免样本内刷分。

## 4. 验证与调参方法学(walk-forward + 粗到细调参)

单次 train/val 切分挡不住本 loop——它跑 K 轮、每轮都拿同一个 val 择优,反复择优会把验证段"吃成"样本内(多重比较 / 验证集泄漏)。故采用 **walk-forward 滚动验证**:沿历史滚动多个前后相接的窗口,每 fold 在 train 段调参、紧接的 val 段验证,整体前移。一个候选要拿高分,必须在**多个互不相同的历史时段上同时**样本外表现好,跨 fold 一致性本身即防过拟合闸门。

### 窗口:滚动(rolling)
- **train 固定长度、整体前移**(非锚定扩展),不让远古陈旧行情压着近期——契合 crypto regime 切换快。窗口长度、fold 数为 plan 阶段参数,受下方算力预算约束。

### 为什么必须"分段"且"多 fold"(rationale,防实现阶段图省事退回全量调参)
- **为什么分段**:调参=在一堆参数里挑"在这段历史上得分最高"的那组,一旦某段数据参与了挑选,它的得分就被污染成乐观的(是 K 次带噪抽样的最大值,天生向上偏),不再代表未来。所以必须留出一段没参与任何选择的数据来诚实评估——"没见过的数据"才是未来、才是实盘。
- **为什么多 fold 而非一个**:①单个 val 段=一次运气抽样(碰巧牛市则"只会追涨"的策略看着神);②本 loop 跑 K 轮、每轮拿 val 择优,**单个 val 会被"选成样本内"**(与全量调参同病、升一层);③单 fold 只有一个数字,算不出 median/离散/灾难门所需的**分布**。多 fold 用算力换"抗运气+防选择泄漏+能测稳定性与尾部"。

### 双层评估(勿混)
- **参数扫描**在**每个 fold 的 train 段内**做,选出的参数应用到该 fold 的 val 段。每个 fold 内部**参数是冻结的**(train 调一次、val 段跑到底不重调),这正是"冻结部署"的诚实模拟(见下)。
- **LLM 结构编辑**这层,用**跨 fold 汇总的样本外指标**给每个候选结构打分、择优。

### 边界隔离(embargo / purging)
- train 与 val 之间插一段 **embargo(隔离带)**,并 purge 掉跨界样本。原因:本系统有**有状态信号**(rolling window、trailing、confirm 计数),跨在 train/val 边界上的滚动窗口会把 train 尾部信息泄进 val 开头。这是业界 walk-forward 标准动作。

### 冻结部署语义(本轮:部署冻结对象,非定期重调参)
- **部署对象 = 冻结**:结构+参数一次定死,上线后零自动变动;重优化=人工重跑本 loop(受审批),非活体自调参。
- **每个 fold 恰好诚实模拟它**:fold = "近期窗口调一次参 → 冻结向前跑";与部署动作("最近窗口调一次参 → 冻结上线")**同一套动作**,故 walk-forward 汇总是对所部署对象的诚实估计(消除了"逐 fold 重调却只部署一次"的不一致)。
- **唯一校准的旋钮:val 段长度 = 打算冻结上线的时长 H(复查视界)**。冻结对象会随市场偏离拟合窗口而**衰减**;val 太短只测到最新鲜那段、测不到衰减 → 高估。故 val=H 让每个 fold 测到冻结实例**完整暴露期**的衰减。衰减度量与失效判断见 §7。
- **三个窗口参数的含义**:train 长度=够稳地调出参数;**val 长度=H(负责测衰减)**;fold 步长=只管取够独立探针+覆盖够多 regime(见 §6 市况分类),与任何节奏无关(冻结没有节奏)。

### 参数扫描机制(内层)
- **粗到细网格(2 级)**:第 1 遍大步长宽范围铺开定位最优区,第 2 遍只在赢家周围收窄细步长精定。比穷举省一个量级,是付得起 walk-forward N 倍开销的关键。全程确定性 → 满足评测 ⑤。
- **选 robust-max(参数平台)而非裸 argmax**:业界有名的 **plateau vs island** 概念——取"周围一圈也都不错的平台中心",对参数小扰动不敏感;裸尖峰一到样本外就废。粗到细"对窄峰失明"恰好与此同源(窄到粗网格能跨过的峰,正是我们不想要的脆弱尖峰)——粗扫时就按 robust-max 选区域去细扫。
- **可调参与范围**:每个 signal kind 自带**默认范围**兜底,LLM 生成/改结构时可**收窄或覆盖**。
- **同时调参个数硬封顶**(如 ≤3-4,plan 阶段定值):维度过高就让 LLM 挑最关键的几个调、其余取默认。这是控 walk-forward 算力的主闸。
- **网格前提写死**:粗到细网格成立的前提是"维度硬封顶到很小";维度一旦上去,正道是 random/Bayesian(代价是破 ⑤ 决定论),留远期。

#### 粗到细 worked example(在一个 fold 的 train 段内)
以一个 RSI 均值回归策略、2 个可调参为例:`T`=RSI 超卖阈值(RSI<T 买),`stop`=止损距离%。评估一个参数组 = 拿它在该 fold 的 **train 段**跑一次回测、算 §3 得分。

**第 1 遍(粗扫)**,大步长稀网:
```
T    ∈ {20, 25, 30, 35}      stop ∈ {2%, 4%, 6%}   → 4×3=12 次回测
          stop=2%  stop=4%  stop=6%
T=20       0.8      1.1      0.9
T=25       1.0      1.5      1.2
T=30       1.2     [1.6]     1.4     ← 这一片都高
T=35       0.7      1.3      0.6     ← 忽高忽低=尖峰嫌疑
```
**robust-max(选平台,非裸最高格)**:对每格算"自己+邻居"的聚合(邻域均值,或更保守取邻域最小值),选聚合最高者。`(T=30,stop=4%)` 周围一圈都不错 → 稳健;某处孤立 1.7 但四周掉到 0.6 → 邻域聚合低,淘汰。→ 赢家区域 ≈ (30, 4%)。

**第 2 遍(细扫)**,只在赢家 ±1 粗步长内、小步长:
```
T ∈ {28,29,30,31,32}   stop ∈ {3%,3.5%,4%,4.5%,5%}   → 5×5=25 次回测
```
再 robust-max → 比如 `(T=29, stop=4.5%)` = 该 fold 选出的参数,拿去 val 段跑出 OOS 分。

**一般算法**:`optimize(ranges) = 粗网格→逐点回测§3→robust-max 定盆地→盆地内细网格→逐点回测→robust-max 定参`。

**成本**:12+25=**37 次**;若一上来细步长铺满(16×9)=**144 次** → ~4× 差,维度/分辨率越高差越大。

**三个 plan 阶段定值**:①邻域=n 维 Moore 邻域(保守取最小值/宽松取均值);②赢家落在粗网格边缘 → **夹在声明范围内**(不在 sweep 偷偷越界,要放宽由 LLM 下轮显式放宽 range);③多个分离平台 → 只钻最好的一个盆地(要覆盖多盆地靠 LLM 结构编辑那层,不把 sweep 复杂化)。

### 候选打分:中心 − 离散惩罚 − 灾难门
每个 fold 的 OOS 分 = §3 的目标函数(walk-forward 不替换目标,只跨 fold 聚合,不重复计分)。聚合成候选总分:
- **中心趋势 = fold 间中位数**:抗单 fold 异常;均值会被某个爆好 fold 拉高、掩盖其余烂 fold。
- **离散惩罚 = 减 λ × fold 间离散度(std 或 IQR)**:奖励"稳定还行"胜过"忽好忽坏";跨 fold 方差大 = regime 敏感 = 上线易翻车(呼应 §6 regime-aware)。
- **灾难门(硬,一票否决)**:任一 fold 触及回撤上限 / 超 X% 的 fold 样本外为负 → 直接否决,不看中位数。挡住"中位数漂亮、藏一个 −80% fold"的候选;select-over-K-rounds 最易挑出这种高中心+隐藏尾部的候选。
- **总分 = median(folds) − λ·dispersion(folds)**,再过灾难门。
- **λ 挂用户偏好**:与 §3 同一个偏好旋钮——激进→λ 小(更看中位数)、稳健→λ 大(更罚离散)。同一旋钮既调 fold *内*风险惩罚(§3)又调 fold *间*一致性惩罚,口径统一。

### 按试验次数给冠军打折(Deflated-Sharpe 思路)
- 本 loop 是 K 轮 × 每轮多候选的**多重测试**——试的越多,冠军的指标越可能是运气。采纳 López de Prado 的 **Deflated Sharpe Ratio** 思路:**冠军的最终指标按累计试验次数解析地打折**,而非手感降权。这是"多重选择偏差 + 小样本"直觉的严谨版。
- 可选:输出 **PBO(回测过拟合概率)** 作为一个评测/报告指标。
- **有意不上 CPCV**:组合净化交叉验证(打乱重排时间块出多路径)更强,但破坏严格时间前后序,与 regime 分类(§6)、冻结部署的"forward-in-time"语义冲突。停在 walk-forward + plateau + embargo + DSR 打折,是我们约束下的最优点。

### 冷启动兜底
- 接顶层 §7 信息保真:链上/情绪历史不够深时凑不出足够 fold → **自动减少 fold 数并把结果标为低置信**,而非假装跑了完整 walk-forward。

### 算力预算
- walk-forward 把回测次数乘上去(N folds × 参数网格 × K 轮)→ plan 阶段须**封顶 fold 数、控制网格大小**;与停止条件、⑦ 相容。
- 评测 ⑦:择优版本的**跨 fold 汇总样本外指标** ≥ 初始版本(不倒退),且内环封顶轮数内必停(不死循环)。

## 5. 执行形式

- 优化以**后台任务**运行,复用现有事件/SSE 架构**阶段性上报每轮进度**(轮次、当前最优、跨 fold 汇总指标)。
- 跑完把**最优版本 + 优化轨迹**交回;不阻塞对话。
- 失败/超时:保留已产出的最优版本与轨迹,任务标失败原因,不静默丢弃。

## 6. 绩效记忆(L1 / L2:填充顶层长期记忆)

顶层 §6 定义了 trade subagent 的**短期(session 内)+ 长期(跨 session 持久)**两层记忆架构。本节定义长期记忆里**"策略绩效"这类内容**的写入与结构——它是把 C 从"一次性优化器"变成**真闭环**的关键(没有它,每条策略跑完即忘)。"用户偏好"那类长期内容不在 C,归顶层/交互层。

### L1 —— per-strategy 绩效日志(底层,必做)
- 按 strategy_id 归档每轮 `{版本, 参数, 每fold + 跨fold汇总指标}` 与实盘成交结果。
- 供本策略优化轨迹与复盘。

### L2 —— 跨策略教训记忆(一等组件)
- **一条教训 = 结构化标签 + 一句反思文本**:
  - 标签:**信号组合**(用了哪些 signal 家族/kind)+ **市况**(趋势 / 震荡 / 高低波,见下)+ 结果倾向(样本外达标 / 失效)。
  - 反思文本:LLM 一句话总结(如"RSI+净流出组合在震荡市样本外反复回撤")。
- **检索键 = 信号组合 + 市况**:生成新策略时,按候选的信号组合 + 当前市况拉相关教训注入 LLM 上下文。
- **市况打标**:每条教训在写入时给当时的市场状态打标签(见下"市况分类"),这是按市况检索的前提,作为 L2 的必要步骤。
- **只吸收样本外验证过的结论**:与 §4 防过拟合绑定,避免把样本内偶然当规律记进记忆。

### 实盘 vs 回测对账(divergence,校准信号——闭合反馈环)

对应顶层 §6 长期记忆的第 2 类内容。C 的部署前内环是对一个*未经校验的模型*(回测)做优化;唯一的 ground truth 是实盘 P&L。此项把 loop 从**开环**(优化完撒手)补成**闭环**(实盘结果回流校准)。

- **产出**:策略部署后,实盘 P&L 攒够(达到最小样本/时长门槛)即与其当初的回测预测对账,算出 `divergence = {predicted_metrics, realized_metrics, gap}`(如回测 Sharpe 2、实盘 0.3)。L1 本就归档实盘成交,divergence 是在其上的一步投影,几乎不增构建量。
- **沉淀**:
  - 轻——标记该 strategy_id 过拟合(进 L1,拉低其复用权重)。
  - 重——若同类反复偏乐观,升格为 L2 教训"某 signal-combo 的回测系统性偏乐观",生成时规避。
- **价值**:这是记忆里唯一能学到"回测与现实的差距"的信号;没有它,L1/L2 学的都只是"回测世界里的教训"。

### 市况分类(regime:报告拆分 / 衰减 / 失效 / L2 打标 共用)

轻量、确定性、可解释;**二维标签**,共 6 档。用于 per-regime 报告拆分、衰减 regime 条件化(§7.2)、失效 regime 离场(§7.3)、L2 打标检索;**不对策略开放为 signal**(自适应策略属远期)。

**分类法(二维 × 6 档)**:

|  | 高波动 | 低波动 |
|---|---|---|
| **趋势上行** trending_up | ✔ | ✔ |
| **趋势下行** trending_down | ✔ | ✔ |
| **震荡** ranging | ✔ | ✔ |

- **方向轴(3 值:trending_up / trending_down / ranging)**:**ADX + Hurst 投票**——ADX 量趋势*强度*(高如 >25=有强趋势)、Hurst 量*性质*(>0.55 持续/趋势,<0.45 均值回归);两者**都**指向趋势(ADX 高 **且** Hurst>0.55)才判趋势(保守 AND,少误判),否则 ranging;趋势的**上/下符号**由 +DI/−DI 或价格斜率定。
- **波动轴(2 值:high / low)**:**ATR / 已实现波动的历史百分位**分档(如 >70 分位=high)。
- **数据来源**:全部从价格/K 线现算(ADX、Hurst、ATR);实盘与回测**共用同一算法**(单一代码源,延续顶层原则),保证打标一致。阈值(ADX 界、Hurst 0.55/0.45、ATR 70 分位)为 plan 阶段参数。
- **调研依据**:ADX/Hurst/Choppiness/Variance-Ratio 是同一问题的不同镜头,轻量组合即足;HMM/聚类/视觉 DL 对"打标签"属过度工程(见顶层 §11 参考)。

**怎么按 regime 拆回测结果(逐 bar 打标 → 分桶)**:
```
回测逐 bar:
  1. 用该 bar 之前的窗口算 ADX/Hurst/ATR → 给这根 bar 贴 1/6 档标签
  2. 把该 bar 的策略收益/成交,归入对应桶
最后:每桶单独算指标 → 如"ranging+高波:收益 X、回撤 Y"
```
- 产出的 per-regime 指标喂给:诊断摘要→LLM(弱点归因)、衰减 regime 条件化、失效 regime 离场、L2 打标。
- **抗抖动(plan 阶段)**:regime 逐 bar 算会在边界反复翻,需**标签持续 N 根 bar 才切换**,否则分桶被噪声打碎。

### 存储
- **复用现有 `eventStore`**(交易结果本就是事件),L1/L2 在其上做投影/检索,不另起并行存储。独立于项目级 `memory/`。

## 7. 部署、衰减度量与失效判断

### 7.1 部署边界
- 内环全程在**回测/历史**上迭代,不碰实盘。
- 冠军结构用**最近窗口调一次参**得到上线参数(与 §4 每个 fold 的动作同构)。
- 择优候选:**paper/shadow 自动部署**;**live 一律发 approval 走现有审批门**。
- **冻结:上线后零自动参数变动**;重优化=人工重跑 loop,新版本 live 晋级照走审批。
- 评测 ⑥:对抗试验断言内环**永不**自动产出 live 部署。

### 7.2 衰减度量(decay)
冻结策略随市场偏离拟合窗口而衰减。**同一套滚动指标,回测里算衰减(预测)、实盘里盯衰减(反应)**,延续 single-source 精神。

- **算法**:把所有 fold 的 val 段按"距调参 t 天"**对齐到 t=0**,在 val 段内滚动算指标(**滚动超额收益 / 滚动 Sharpe**,用超额是为剥离"市场整体变难"的混淆),**跨 fold 平均**同一 t 的值 → 一条稳健的**衰减曲线**。
- **摘要**:①衰减斜率(回归斜率);或 ②半衰期("边际优势每 X 天减半"),半衰期直接定 H(取 H≈1~2 个半衰期)。
- **诚实说明**:衰减本质与 regime 漂移耦合(冻结策略衰减正因市场漂离其拟合 regime),故衰减既报整体、也可按 regime 条件报,分清"变旧"vs"换了行情"。

### 7.3 失效判断(invalidation / kill-switch)
冻结策略必然有天失效;**没有预先承诺的失效线就会犯"亏着还盼回来"的经典错**。失效线**全部从回测自身分布推出**,不拍脑袋。四条、分软硬:

| 触发 | 判据(来自回测分布) | 响应 |
|---|---|---|
| **爆仓线(硬)** | 实盘回撤 ≥ 灾难门阈值,或 ≥ 回测最差 fold 回撤 × 余量 | **自动停止开新仓** + 人工介入 |
| **跑输地板(软)** | 滚动窗口实盘指标 < 回测 fold 分布地板(最差 fold / 5 分位),且持续一段 | 标记、触发人工重优化 |
| **regime 离场(软)** | 当前 regime ∉ 该策略回测中表现达标的 regime 集 | 降级 / 告警(接 §6 市况) |
| **视界到期(软)** | 距调参时长 > H | 强制复查(H 之外无任何证据它还有效) |

- **硬触发只做"停止/减仓",不需审批**:停手永远允许、只降风险,不是需审批的新 live 动作 → 与安全不变量自洽。
- **实盘盯的指标 = 7.2 算衰减用的同一滚动指标**;"实盘衰减快于回测预测"本身即 divergence 信号(§6),自然并入失效判断。
- 失效事件回流记忆:"该结构 X 天后失效 / regime Y 翻转时失效" → 沉淀 L2。

## 8. 交付边界(C 完成即)

agent 生成一份策略后可发起后台优化 → 内环自动扫参 + LLM 改结构 + 样本内外验证 → 产出样本外达标的最优版本 → 自动部署到 paper/shadow(或对 live 发审批)。至此顶层"生成→回测→优化→部署"闭环打通。
